# AGENT.md — AI Agent Guide for Portuguese for Kids Mobile

This file describes the architecture, conventions, and non-negotiable rules an AI coding agent must follow when working on `Portugese-for-Kids-Mobile`.

---

## Project Purpose

Expo SDK 58 / React Native (`0.88.1`) TypeScript mobile app teaching **children aged 7+** European Portuguese through flashcards, 8 interactive games, and AI-generated conversational stories.

Companion repositories in the same parent directory:
- `../Portugese-for-Kids` — source-of-truth web app for vocabulary, grammar datasets, and scoring logic
- `../Portugese-for-Kids-Backend` — Spring Boot REST API on Cloud Run (`/api/story`, `/api/image`, `/api/user/*`)

## Key Design Decisions

### 1. Core Data Sync Pipeline (`scripts/sync-core.mjs`)
- `src/core/**` and `src/data/marketItems.mobile.ts` are synced directly from `../Portugese-for-Kids`.
- **Never** edit generated files under `src/core/` or `src/data/marketItems.mobile.ts` by hand. Edit `../Portugese-for-Kids` first, then run `npm run sync-core`.
- `npm run sync-core:check` runs in CI (`.github/workflows/ci.yml`) and fails on hash mismatch against `core.lock.json`.
- `MOBILE_EXCLUDED_MARKET_ITEMS` in `scripts/sync-core.mjs` filters out `wine` and `beer` so the mobile dataset stays age-appropriate (`7+`).

### 2. Split TypeScript Configuration (`tsconfig.json` vs `tsconfig.core.json`)
- App code in `src/` enforces `"strict": true` and `"noUncheckedIndexedAccess": true` (using project references via `tsconfig.core.json`).
- Synced web code in `src/core/` compiles via `tsconfig.core.json` (`"noUncheckedIndexedAccess": false`, `emitDeclarationOnly: true`, `.tsc-core/`) so web files sync cleanly without modifying upstream code.
- Always run `npm run typecheck` (`tsc -b && tsc --noEmit`) after edits.

### 3. Metro Resolver & React Native 0.88 Package Exports (`metro.config.js`)
- **Do not** set `config.resolver.unstable_enablePackageExports = false`. React Native `0.88.1` exposes `react-native/asset-registry` exclusively via `package.json` `"exports"`, so disabling package exports breaks every image/audio `require(...)` asset in Metro.
- Firebase `13.3.0` (`@firebase/app` and `@firebase/auth`) resolves its `react-native` entrypoints cleanly with Expo SDK 58's default `unstable_conditionsByPlatform` (`['react-native']`).

### 4. Continuous Native Generation (CNG)
- Native folders `ios/` and `android/` are gitignored and generated by `expo prebuild` / `npx expo run:android`.
- Put all native config, URL schemes, permissions (`AD_ID` blocked), and plugins inside `app.config.ts`. Never rely on manual edits inside `android/` or `ios/`.

### 5. UI-Thread Animations & Skia Jigsaw
- Keep drag tracking (`useSharedValue`), transforms (`useDerivedValue`), and snap springs (`withSpring`) on the Reanimated UI thread inside worklets; bridge back to React state only on gesture completion via `scheduleOnRN`.
- Never mutate `SharedValue` arrays inside React hooks after initialization in a way that trips `react-hooks/immutability` — store piece coordinates in a plain keyed `SharedValue<Record<string, number>>` and update via immutable object spread inside worklets.

### 6. Firebase Auth Persistence
- Always initialize Firebase Auth with `initializeAuth(app, { persistence: getReactNativePersistence(AsyncStorage) })` (guarded by `getApps()[0]` reuse so Fast Refresh does not re-initialize).
- Local testing uses `.env.local` (gitignored); never commit real `AIzaSy...` keys into `.env.example` or source files.

### 7. Navigation & Shared Contracts
- **Navigation model:** State-driven mode switcher in `src/App.tsx` (matching the web app — **do not** add Expo Router unless explicitly requested).
- **Bilingual by contract:** Every screen, game, and `accessibilityLabel` respects `language: 'en' | 'tr'`.
- **Speech wrapper:** When Phase 1 adds audio, route all TTS through `src/audio/speech.ts` and call `cancelSpeech()` on unmount.
- **Game contract:** Every game renders `GameScoreBadge` and reports points via `onScore(pts)` backed by unit-tested pure scoring helpers.

## Children's Privacy, Security & Compliance (Non-Negotiable)

- **Zero ads & 100% free:** Never add ad SDKs, behavioral tracking, or advertising IDs (`com.google.android.gms.permission.AD_ID` remains in `android.blockedPermissions`).
- **No PII in logs or crash reports:** Zero `console.log` in committed code; never log auth tokens, email addresses, or full request bodies.
- **Parental gate:** Every outbound URL, mailto link, store review prompt, or account action must pass through a parental gate.
- **No free-text public names:** Leaderboard display names use the child-safe nickname picker (`Adjective + Animal`).
- **Offline resilience:** Flashcards, games, template stories, and the telemetry outbox must work without network connectivity.

## Running & Validating Changes

```bash
npm run sync-core:check   # Verify zero drift against ../Portugese-for-Kids
npm run typecheck         # tsc -b && tsc --noEmit
npm run lint              # eslint .
npm test -- --ci          # Jest unit tests (jest-expo)
npx --yes expo-doctor     # Expo SDK 58 config & dependency audit
```

Look up current Expo SDK 58 documentation (`https://docs.expo.dev/versions/v58.0.0/`) before using unfamiliar Expo/RN APIs.

## What NOT to Do

- **Do not** hand-edit files in `src/core/` or `src/data/marketItems.mobile.ts` (edit `../Portugese-for-Kids` and run `npm run sync-core`).
- **Do not** commit `ios/`, `android/`, `.idea/`, `.tsc-core/`, `.env.local`, or `node_modules/`.
- **Do not** disable `unstable_enablePackageExports` in `metro.config.js`.
- **Do not** use `any` — use `unknown` + type narrowing at boundaries.
- **Do not** commit, push, submit to App Store Connect / Google Play, publish production OTA updates, or change Firebase / Google Cloud Console configuration without explicit user approval.
